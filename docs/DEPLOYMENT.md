# Развёртывание

**Yandex Cloud — единственная целевая продакшн-площадка.** Тулинг других площадок в проект не переносится: две инфраструктуры в одном репозитории означают, что обе полузаброшены.

> **Кода развёртывания в репозитории пока нет.** Этот документ описывает намеченную архитектуру и решения, которые нужно принять до её реализации. Инфраструктура появляется после Wave 4.

---

## 1. Почему Yandex Cloud

Требование локализации персональных данных в российском регионе. Лиды содержат контактные данные; они не покидают выбранный регион ни в основной базе, ни в резервных копиях, ни в логах.

Следствие для LLM: DeepSeek — внешний провайдер за пределами контура. Поэтому граница проведена жёстко и проверяется правилом AC-2: модель получает ключевые запросы, структуру брифа и текст статьи, но **никогда** — содержимое `leads` и `attribution_touches`. Коммерческая информация пересекает границу; персональные данные — нет.

## 2. Целевая архитектура

| Компонент | Сервис | Назначение |
| --- | --- | --- |
| Backend / API | Serverless Containers или Compute Cloud | `api.pipupi.ru`, образ из `backend/Dockerfile` |
| Фоновые задачи | Тот же образ, другая точка входа | Дренаж outbox, периодические задачи |
| База данных | Managed Service for PostgreSQL | Единственное хранилище состояния |
| Объектное хранилище | Object Storage | Приватный бакет — файлы; публичный — статика сайта и приложения |
| CDN | Cloud CDN | Раздача `pipupi.ru` и `app.pipupi.ru`, редирект `www`, TLS |
| Секреты | Секрет-хранилище площадки | Никогда не репозиторий |
| Логи | Cloud Logging | Структурированные логи всех точек входа |
| Мониторинг | Monitoring | Метрики, алерты |

Один процесс API. Фоновые точки входа добавляются, когда появится конкретная периодическая или долговременная работа, — и **из того же образа**, а не как отдельный сервис.

## 3. Открытый вопрос: UUIDv7

**Статус: не решён. Требует проверки перед Wave 3.**

Шаблон-основа использует первичные ключи UUIDv7, генерируемые базой через нативную функцию `uuidv7()`, доступную начиная с PostgreSQL 18.

**Что нужно проверить в Yandex Managed Service for PostgreSQL:**

1. Максимальная доступная мажорная версия PostgreSQL.
2. Есть ли нативная `uuidv7()` в этой версии.
3. Доступно ли расширение `pg_uuidv7` в списке разрешённых расширений.
4. Доступно ли расширение `pgvector` — оно нужно для кластеризации тем.

**Предпочтительный fallback, если PostgreSQL 18 недоступен:**

- UUIDv7 генерируется **приложением**;
- тип колонки остаётся нативный `uuid` — не текст, не bytea;
- порядок сортировки по времени сохраняется, индексы работают так же;
- **прямые записи в обход backend запрещены** — это условие корректности fallback, а не пожелание.

Что теряется при fallback: единый способ генерации ID для писателей, не проходящих через Prisma — прямой SQL, импорты, сторонние процессы. В MVP таких писателей нет: вся запись идёт через backend. Именно поэтому запрет на прямые записи становится частью решения, а не отдельной рекомендацией.

Локальная разработка остаётся на `postgres:18-alpine` в любом случае — совместимость вниз полная.

**Решение записывается в [CHECKLIST.md](../CHECKLIST.md) после проверки.** До этого схема не фиксируется.

## 4. Health checks

| Эндпоинт | Назначение | Поведение |
| --- | --- | --- |
| `/health` | Общий статус | Быстрый ответ без внешних зависимостей |
| `/health/live` | Liveness | Процесс жив. **Не** проверяет базу — иначе кратковременная недоступность базы вызовет перезапуск, который её не починит |
| `/health/ready` | Readiness | Готов принимать трафик: база отвечает, миграции применены |

Разделение liveness и readiness — не формальность. Перезапуск контейнера из-за недоступной базы удлиняет инцидент вместо его разрешения.

## 5. Резервное копирование

| Что | Как |
| --- | --- |
| База данных | Автоматические резервные копии Managed PostgreSQL, срок хранения — не менее 7 дней |
| Point-in-time recovery | Включён |
| Регион копий | Тот же российский регион, что и основная база |
| Объектное хранилище | Версионирование на приватном бакете |
| Опубликованная статика | Восстанавливается пересборкой из базы — резервная копия не требуется |

**Восстановление проверяется на практике до запуска.** Непроверенная резервная копия — это предположение о резервной копии, а не резервная копия. Процедура и время восстановления записываются.

## 6. Секреты

| Правило | — |
| --- | --- |
| Хранение | Секрет-хранилище площадки |
| В репозитории | Только `*.env.example` с явными плейсхолдерами |
| Подстановка | Через механизм площадки. **Никаких ручных `sed`, `perl` и shell-подстановок** в спецификации развёртывания |
| Ротация | Плановая; внеплановая — немедленно при подозрении на компрометацию |
| Утечка в Git | Удаления файла **недостаточно**: секрет остаётся в истории и подлежит отзыву и перевыпуску |

Секреты, необходимые продакшну: строка подключения к базе, ключ подписи JWT, ключ DeepSeek, ключи доступа к объектному хранилищу.

**Ключ DeepSeek не появляется ни в одном файле репозитория, ни в одном документе и ни в одном сообщении чата.**

## 7. Логи и мониторинг

**Логи:** структурированные, с идентификатором корреляции, в Cloud Logging.

Что **не** попадает в логи никогда: содержимое персональных данных лидов, значения токенов и секретов, полные тексты промптов и ответов модели (пишется хеш промпта и метаданные запуска — этого достаточно для отладки и учёта стоимости).

**Метрики под наблюдением:**

| Метрика | Почему важна |
| --- | --- |
| Задержка и коды ответов API | Базовое здоровье |
| Глубина очереди outbox | Растущая от запуска к запуску — сигнал, что дренаж не успевает. Это и есть то самое **измерение**, которое может открыть разговор об очереди-сервисе |
| Ошибки и задержки задач | Здоровье фоновой работы |
| Ошибки и задержки вызовов LLM | Внешняя зависимость |
| Накопленная стоимость LLM за месяц | Против `LLM_MONTHLY_COST_CAP_RUB` |
| Соединения и медленные запросы базы | Ранние признаки деградации |
| Срок действия TLS-сертификатов | Предсказуемый сбой, который стыдно допустить |

**Алерты:** недоступность readiness, рост очереди outbox, всплеск ошибок 5xx, приближение к пределу стоимости LLM, приближение срока сертификата, сбой резервного копирования.

## 8. Откат

| Слой | Стратегия |
| --- | --- |
| Backend | Возврат на предыдущий образ. Образы неизменяемы и тегированы коммитом |
| База | **Миграции только совместимые вперёд.** Откат кода не должен требовать отката схемы |
| Публичная статика | Повторная сборка из известного коммита с последующей инвалидацией CDN |
| Данные | Восстановление из резервной копии — крайняя мера, с осознанной потерей окна |

**Правило совместимых миграций:** сначала добавляем колонку и пишем в оба места, потом переключаем чтение, потом удаляем старое — отдельными релизами. Миграция, ломающая предыдущую версию кода, лишает возможности откатиться именно тогда, когда откат нужнее всего.

## 9. Порядок первого развёртывания

1. Проверить версию PostgreSQL и доступные расширения → закрыть вопрос UUIDv7 (раздел 3).
2. Создать Managed PostgreSQL в российском регионе, включить резервные копии и PITR.
3. Создать бакеты объектного хранилища: приватный и публичный, раздельно.
4. Настроить CDN на публичный бакет, включая редирект `www` → apex.
5. Завести секреты в хранилище площадки.
6. Собрать и опубликовать образ backend.
7. Развернуть API, проверить `/health/ready`.
8. Применить миграции.
9. Настроить DNS и TLS по чек-листу из [DOMAINS.md](DOMAINS.md).
10. Собрать и выложить `website` и `webapp`.
11. Проверить: host-only cookie авторизации не приходит на публичный сайт; обе политики CORS работают; canonical корректны.
12. Проверить восстановление из резервной копии.
13. Настроить алерты.

## 10. Чего не делаем

| Не делаем | Почему |
| --- | --- |
| Kubernetes | Один backend-процесс и одна база. Оркестратор здесь — чистые накладные расходы |
| Микросервисы | Вся предметная логика умещается в одну транзакционную границу |
| Redis, Valkey, Kafka, RabbitMQ, Elasticsearch | Ни одна задача MVP не требует. Порядок добавления — раздел 6 [ARCHITECTURE.md](ARCHITECTURE.md) |
| n8n | Оркестрация живёт внутри монолита |
| Вторая облачная площадка | Одна выбрана, тулинг остальных не заводится |
| ISR и SSR на публичном сайте | Чистый SSG. Публикация — событие в outbox, а не рантайм-рендеринг |
