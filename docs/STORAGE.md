# Хранилище объектов

Backend владеет доступом к объектному хранилищу через **один провайдер-нейтральный порт** `ObjectStoragePort`. Это сервис уровня backend, а не продуктовый модуль.

> **В MVP модуль загрузки файлов не активируется.** Порт и драйверы наследуются из шаблона-основы и остаются доступными; продуктового модуля загрузки медиа мы не заводим. В реестре возможностей [CHECKLIST.md](../CHECKLIST.md) это состояние `available`. Публикация статики сайта при этом использует хранилище с первого дня.

---

## 1. Порт

| Операция | Назначение |
| --- | --- |
| Presigned upload | Подписанная ссылка на загрузку — байты идут мимо backend |
| Presigned download | Подписанная ссылка на скачивание приватного объекта |
| HEAD | Проверка существования и метаданных |
| Ranged read | Частичное чтение |
| Delete | Удаление объекта |

Драйверы: файловая система (локально, ничего устанавливать не нужно) и S3-совместимый (Yandex Object Storage в продакшне). Один контрактный набор тестов прогоняется против обоих — поэтому переход между ними является настройкой, а не переписыванием кода.

**`backend/src/providers/storage/**` — единственное место, где появляется SDK объектного хранилища.** Правило AC-1 запрещает его импорт в слоях `domain`, `application` и `transport` любого модуля. Продуктовый модуль обращается к хранилищу только через порт.

---

## 2. Два бакета, две модели доступа

| Бакет | Содержимое | Доступ |
| --- | --- | --- |
| **Публичный** | Собранная статика `website` и `webapp`, изображения опубликованных материалов | Чтение через CDN. Прямой доступ к бакету закрыт |
| **Приватный** | Всё остальное: рабочие файлы, выгрузки, вложения | Только по подписанным ссылкам с ограниченным сроком |

Смешивать их нельзя. Бакет, который «пока публичный, потом закроем», остаётся публичным.

Публичный бакет **не** содержит: черновиков, неодобренных ревизий, выгрузок с персональными данными, служебных файлов. В нём лежит только то, что уже прошло одобрение и опубликовано.

---

## 3. Разделение ответственности

**Владение, состояние и срок хранения живут в PostgreSQL**, а не в хранилище. Хранилище не может ответить, кому принадлежит файл и завершилась ли загрузка, — это знает только база.

Практически: на каждый объект есть строка в базе с владельцем, состоянием (`pending`, `ready`) и сроком годности подписанной ссылки. Периодическая задача убирает незавершённые загрузки — **сначала объект, потом строку**. Обратный порядок оставил бы в хранилище файл, на который ничто не ссылается и который никто больше не будет искать.

---

## 4. Ключи объектов

Ключи генерирует backend. Они **не содержат персональных данных**: ни имён, ни телефонов, ни email, ни исходных имён файлов, загруженных человеком.

Причина не в эстетике. Ключ объекта попадает в логи CDN, в логи прокси, в заголовки `Referer` и в подписанные ссылки, которыми делятся. Персональные данные в ключе утекают во все эти места одновременно и незаметно.

## 5. Публикация статики сайта

Публикация материала (шаг 16 конвейера, [CONTENT_PIPELINE.md](CONTENT_PIPELINE.md)) выполняется через outbox:

```
одобренная ревизия
  → сборка Astro
    → выгрузка в публичный бакет
      → инвалидация CDN
```

Через outbox, а не «кнопкой в CI», потому что публикация обязана оставаться внутри транзакционной границы одобрения: только одобренная ревизия имеет право попасть в бакет.

Задача идемпотентна: повторный прогон той же публикации приводит к тому же результату и не создаёт дублей.

---

## 6. Локальная разработка

Драйвер файловой системы. Ничего устанавливать не нужно, S3-совместимый контейнер поднимать не обязательно.

Тесты S3-драйвера — категория `*.live.test.ts`: они требуют внешнего сервиса и запускаются отдельно, чтобы `bun run test` оставался работоспособным на машине без запущенных контейнеров.

## 7. Продакшн

| Параметр | Значение |
| --- | --- |
| Сервис | Yandex Object Storage, S3-совместимый |
| Регион | Российский, тот же, что и база |
| Версионирование | Включено на приватном бакете |
| Публичный доступ к приватному бакету | Запрещён |
| Ключи доступа | Только в секрет-хранилище площадки |

Переменные окружения — раздел «Публикация и хранилище» в [DEPLOYMENT.md](DEPLOYMENT.md). Ключи доступа в репозитории присутствуют только плейсхолдерами.
