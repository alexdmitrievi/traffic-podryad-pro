## 8. Интеграции

| Порт | Драйвер в MVP | Конфигурация |
| --- | --- | --- |
| `LlmPort` | DeepSeek | `DEEPSEEK_BASE_URL=https://api.deepseek.com`, `DEEPSEEK_MODEL=deepseek-v4-pro`. Ключ — только в секрет-хранилище, никогда в репозитории. Боевой вызов требует `DEEPSEEK_INPUT_PRICE_USD_PER_1M`, `DEEPSEEK_OUTPUT_PRICE_USD_PER_1M`, `DEEPSEEK_USD_TO_RUB_RATE` и `LLM_MONTHLY_COST_CAP_RUB` — иначе процесс не стартует |
| `KeywordSourcePort` | CSV-импорт | Без сетевых вызовов |
| `PublishingPort` | Внутренний сайт на Astro | Сборка → Object Storage → инвалидация CDN |
| `ObjectStoragePort` | S3-совместимое Yandex Object Storage | Приватный и публичный бакеты раздельно |
| `MessagingPort` | **отсутствует** | В репозитории нет адаптера отправки |

## 9. Одобрение

| Вопрос | Ответ |
| --- | --- |
| Кто одобряет контент и планы в MVP | Пользователь — единственный одобряющий |
| Модель одобрения | Отдельная сущность `approvals`, а не boolean-поле |
| К чему привязано одобрение | К точному content hash одобряемой ревизии |
| Что происходит при изменении контента после одобрения | Одобрение аннулируется автоматически |
| Можно ли опубликовать без одобрения | Нет. Запрещено на уровне схемы БД |
| Автор и одобряющий | Записываются раздельно, даже когда это один человек |
| Политика «одобряющий ≠ автор» | Сейчас выключена. Данные для её включения собираются с первого дня |

## 12. Открытые вопросы

### 12.0. Точка остановки (август 2026)

Wave 4 завершена (коммиты 4a–4f в `main`): сквозной SEO-срез работает локально и
воспроизводится E2E-тестом. Дальше по плану шли gate PostgreSQL (§12.1) и реальный CSV
ключей (§12.2); оба требуют внешних ресурсов, которых на 2026-08-14 нет (реальный
кластер Yandex Cloud и файл ключей), поэтому исполнен следующий кодом шаг — подготовка
боевого DeepSeek (§12.3). Полный порядок дальнейших шагов — раздел «Что будет
реализовано дальше» в README.

### 12.3. Боевой DeepSeek: ревью границы ПДн и учёт стоимости

**Статус: подготовка завершена, живая проверка ждёт ключ.** Это шаг, исполняемый
кодом, — выбран вместо gate (§12.1) и CSV (§12.2), которые блокированы внешними
ресурсами. Решение записано в §12.0.

| Что проверялось | Результат | Как проверено |
| --- | --- | --- |
| Поля payload'ов `LlmPort` не несут ПДн | `пройдено` | `port.ts`: ключи, кластер, продукты, регионы, аудитория, тон, инструкции — и ничего больше |
| Рантайм-guard отклоняет ПДн до записи `llm_runs` | `пройдено` | `pii-guard.ts` сканирует сериализованный payload (email/телефон/ИНН); тесты в `llm.test.ts` и `llm.integration.test.ts` |
| Модуль контента не подмешивает контакты в инструкции | `пройдено` | `modules/content/application/content.ts`: входы LLM собираются только из кластера/брифа |
| AC-2: `providers/llm` не импортирует ПДн-модули | `пройдено` | `architecture:check` в CI |
| Стоимость DeepSeek доходит до предохранителя | `реализовано` | Драйвер считает RUB-копейки из цен и курса; ключ без цен/курса/лимита — отказ стартовать (`env.ts`); unit-тесты `deepseek-driver.test.ts` |
| Живая проверка против реального сервиса | `ждёт ключ` | `bun run --cwd backend test:live` с `DEEPSEEK_API_KEY` в `backend/.env` |

Цены для тарификации берутся со страницы цен провайдера и перепроверяются человеком
перед каждым живым прогоном; с 2026-08-16 вводится пиковая/внепиковая тарификация, в
конфигурацию закладывается пиковая цена как консервативная верхняя граница.
